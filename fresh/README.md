# 1С:Фреш: все объекты в OData одним скриптом

В приложении 1С:Фреш стандартный интерфейс OData включают в форме «Настройка автоматического REST-сервиса» (раздел «Синхронизация данных»). На вкладке «Состав» тысячи галочек, кнопки «Отметить все» нет, а внешнюю обработку во Фреше не запустить. Эти скрипты отмечают всё в открытом окне браузера и проверяют результат по HTTP.

Проверено 15.11.2026 на «Бухгалтерии предприятия» 3.0.211 (3830 наборов OData) и «Рознице» 3.0.14 (2461).

## Файлы

| Файл | Что делает |
| --- | --- |
| `select-all.mjs` | Открывает форму, загружает метаданные, отмечает все группы, начиная с тех, от которых зависят другие (перечисления, ПВХ, планы счетов). Окна зависимостей подтверждает, если 1С добавляет объекты, и отклоняет, если исключает. В конце открывает вкладку «Авторизация». Пароль REST-пользователя и «Сохранить» — за человеком |
| `browser.mjs` | Отдельное окно Chrome со своим профилем (`.work/profile`) и портом DevTools 9333 на localhost. Chrome запускается отдельным процессом: окно не закрывается, когда скрипт завершается или падает |
| `peek.mjs` | Снимок окна и состояние дерева «Состав» во время работы (`.work/peek.png`) |
| `check-odata.mjs` | Сколько наборов опубликовано, по видам, и пробное чтение справочника |

Нужны Node.js 22+ и Google Chrome. В скрипте путь к Chrome для Windows (`C:/Program Files/Google/Chrome/Application/chrome.exe`); на другой системе поправьте его в `browser.mjs`.

## Как запустить

```
npm ci
node select-all.mjs https://<узел>.1cfresh.com/a/<конфигурация>/<область>
```

Адрес приложения виден в адресной строке после входа, например `…/a/ea/1234567` («Бухгалтерия») или `…/a/sbm/1234567` («Розница»). В открывшемся окне войдите во Фреш сами; сессия сохранится в профиле. Журнал — в консоли, по строке на группу: «строк N, уже было отмечено M, отмечено сейчас K». Строки, которые не отметились с двух попыток, перечислены в итоге группы.

Когда скрипт закончит: на вкладке «Авторизация» включите отдельного пользователя, задайте имя и пароль, нажмите «Сохранить и закрыть». Затем создайте рядом со скриптами файл `.env`:

```
FRESH_1C_USER_ODATA=<имя>
FRESH_1C_PASS_ODATA=<пароль>
```

и проверьте:

```
node check-odata.mjs https://<узел>.1cfresh.com/a/<конфигурация>/<область>
```

Ответ `HTTP 200` и число наборов — публикация работает. Скрипты не выводят логин и пароль и не вводят их.

## Что выяснилось по дороге

- Веб-клиент 1С игнорирует события с `isTrusted=false`: `element.click()` из консоли браузера ничего не отмечает. Нужны настоящие клики — через протокол DevTools.
- Быстрые серии пробелов и стрелок 1С теряет: каждая галочка — запрос к серверу. Скрипт отмечает по одной и перед каждым кликом проверяет, что под курсором та же строка и галочка снята; иначе клик по сдвинувшейся строке снимает соседнюю, а «Да» в окне зависимостей снимает пачку.
- Таблица может не доходить до низа окна, строки под её краем есть в DOM, но обрезаны. Видимость строк считается по рамке таблицы, прокрутка — PageDown от последней видимой строки. Колесо мыши в этой таблице не работает.
- Подписи вкладок формы бывают в CSS `::before` с пустым `textContent`; вкладку находят по id `thpage_formN_Состав`. У кнопки «Загрузить метаданные» есть скрытый двойник в меню «Ещё» — искать только видимую.
- Окно зависимостей в «Бухгалтерии» — «Да / Нет», в «Рознице» — «Разрешить / Запретить». Флажок отдельного пользователя в «Рознице» — переключатель.
- Escape закрывает форму без сохранения. Если форма изменена, «Загрузить метаданные» спрашивает «Загрузить метаданные заново? Внесенные изменения будут потеряны» — скрипт отвечает «Нет». Кнопки этого вопроса — `a.press`, а не `.framePress`, как в окнах зависимостей.
- Перечисления в OData не отдельные наборы, а типы полей. Курсы валют (`InformationRegister_КурсыВалют`) в «Состав» Фреша не входят.
